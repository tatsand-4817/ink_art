# インクアート PWA 要件定義書

> Claude Code 引き継ぎ用。リポジトリ直下 `docs/` などに配置し、ピン子(pm-pinko)にこのファイルを読ませてから着手すること。

## 1. 概要

好きな色のインクを水面に垂らした時に広がる模様を、WebGL による流体シミュレーションでリアルタイムに再現するアート制作 Web アプリ(PWA)。

**コンセプト**: 「それっぽい模様」ではなく、実際にインクを落とした時の滲み・渦・混色の挙動を本物志向で再現する。

## 2. ゴールと成功基準

- 画面をタップ/クリックすると、その位置からインクが広がり、水面上で滲む・渦を巻く・混ざる挙動が視覚的に納得できるレベルで再現される
- ユーザーが色を自由に指定でき、複数色を重ねると自然に混色される
- 完成した模様を画像として保存・共有できる
- モバイル(iPhone Safari)で 30fps 以上を維持する

## 3. スコープ

### やること(MVP)

| # | 機能 | 内容 |
|---|---|---|
| F-1 | 流体シミュレーション | WebGL による Navier-Stokes ベースのリアルタイム流体シミュレーション |
| F-2 | インク投下操作 | タップ/クリック/ドラッグでインクを落とす。ドラッグ中は連続投下し、動きの方向が流れに反映される |
| F-3 | インク色選択 | プリセット複数パターン + 数値指定によるカスタム色 |
| F-4 | 台紙(水)の色選択 | ベースとなる水面の色を独立して選択可能 |
| F-5 | 混色 | 複数色のインクが接触した際に自然に混ざる |
| F-6 | 保存 | 現在のキャンバスを PNG 画像として端末に保存 |
| F-7 | 共有 | Web Share API による共有。非対応環境ではダウンロードにフォールバック |
| F-8 | クリア | キャンバスをリセットして最初からやり直す |
| F-9 | PWA 対応 | manifest / Service Worker / オフライン起動 / ホーム画面追加 |

### nice to have(MVP後、優先度順)

| # | 機能 | 内容 |
|---|---|---|
| N-1 | 台紙の質感パターン | 和紙風・マーブル紙風・キャンバス地風などのテクスチャ選択 |
| N-2 | インクの粘度調整 | 広がりやすさ(拡散係数)のパラメータ調整 |
| N-3 | 一時停止/再生 | シミュレーションを止めて構図を確定させる |
| N-4 | Undo | 直前の一投を取り消す |

### やらないこと(スコープ外)

- ギャラリー機能(過去作品の一覧・保存管理)
- SNS 投稿機能・アカウント連携
- ユーザー認証、サーバーサイドのデータ永続化
- 他ユーザーの作品閲覧などのソーシャル要素

## 4. カラー仕様(F-3 / F-4)

### インク色

**プリセット**: 以下のようなテーマ別セットを複数用意する。各セットは 5〜6 色程度。

- モノクロ系(墨・グレー・白)
- ビビッド系(原色に近い高彩度)
- パステル系(低彩度・高明度)
- 和色系(藍・朱・萌黄など)

※ 具体的な色定義はデザイン担当(彩さん)が確定させる。

**カスタム指定**: 以下の入力方法を提供する。

- HEX 入力(`#RRGGBB` 形式のテキスト入力)
- RGB スライダー(各 0〜255)
- HSL スライダー(色相 0〜360 / 彩度・明度 0〜100)

3 つの入力は相互に同期し、どれを操作しても他が追従すること。

### 台紙(水)の色

- インク色とは独立して選択できる
- 同様にプリセット + カスタム指定に対応
- デフォルトは白〜わずかに青みがかった透明水色

## 5. 技術方針

### スタック

- **フレームワーク**: React + TypeScript + Vite
- **描画**: WebGL2(生の WebGL または最小限のラッパー。three.js は流体シミュレーションには過剰なため要検討)
- **PWA**: `vite-plugin-pwa`
- **デプロイ**: Vercel

### 流体シミュレーション

Stable Fluids(Jos Stam)ベースの GPU 実装を採用する。フラグメントシェーダによる以下のパスをフレームごとに実行:

1. **Advection** — 速度場と染料場を速度に沿って移流
2. **Divergence** — 速度場の発散を計算
3. **Pressure(Jacobi 反復)** — 圧力場を解く。反復回数はモバイル性能に応じて調整(目安 20〜40)
4. **Gradient Subtract** — 圧力勾配を引いて非圧縮化
5. **Render** — 染料場を画面に描画

**染料場は RGB 3チャンネルで保持**し、色の混合は染料場上での加算/ブレンドによって自然に発生させる。台紙の色は背景色として合成する。

### 実装上の注意

- 浮動小数点テクスチャ(`EXT_color_buffer_float` / `OES_texture_half_float`)のサポート確認とフォールバックを必ず入れる。iOS Safari では half float を使う
- シミュレーション解像度と表示解像度を分離する(シミュレーションは低解像度、表示はフルサイズで補間)
- `devicePixelRatio` を考慮しつつ、モバイルでは上限を設けて負荷を抑える
- 保存時はシミュレーション結果を高解像度で再描画してから `toDataURL` する(表示解像度そのままだと粗い)
- `preserveDrawingBuffer` の扱いに注意。常時 true にするとパフォーマンスが落ちるため、保存時のみ再描画する方式を推奨

### 参考実装

`PavelDoGreat/WebGL-Fluid-Simulation` が Stable Fluids の GPU 実装として広く参照されている。アーキテクチャの参考にするのは可だが、ライセンス(MIT)を確認の上、丸ごとのコピーではなく本要件に合わせて再構成すること。

## 6. UI 構成

```
┌─────────────────────────────┐
│                             │
│                             │
│      キャンバス(全画面)      │
│      ここをタップ/ドラッグ    │
│                             │
│                             │
├─────────────────────────────┤
│  [色] [水] [保存] [共有] [消] │  ← 操作バー
└─────────────────────────────┘
```

- キャンバスは全画面。操作バーは最小限にしてアート体験を邪魔しない
- 色選択はボトムシート/モーダルで開く。プリセットをタップで即選択、カスタムはタブ切り替え
- 操作バーは数秒操作がないとフェードアウトする案も検討(nice to have)

## 7. 受け入れ基準

- [ ] iPhone Safari 実機で 30fps 以上を維持しながらインクが広がる
- [ ] インクが水面上で滲み、渦を巻き、時間経過で自然に拡散する
- [ ] 2 色以上のインクを近接して落とすと、境界で混色が起きる
- [ ] HEX / RGB / HSL の各入力が相互に同期する
- [ ] 台紙の色を変更すると即座に反映される
- [ ] 保存した PNG が画面表示と同等以上の解像度である
- [ ] Web Share API 対応環境で共有シートが開き、非対応環境ではダウンロードされる
- [ ] ホーム画面に追加でき、オフラインで起動する
- [ ] クリアで初期状態に戻る

## 8. 制約

- 期限: 数週間以内に MVP を形にする
- 新規リポジトリ
- PWA 前提(ネイティブアプリ化は当面考えない)
